## 1. 生活类比与动机：从"现做"到"预制菜"

### 是什么

开发期浏览器吃的是 Vite **现做**的菜（`npm run dev`，5180 端口，改一行立即热更新）；上线吃的是**预制菜**——`npm run build` 一次做好、封装进 `dist/`，之后谁来都直接加热上桌（nginx 纯静态递送）。前后端从此**解耦**：前端是死文件，后端是 API，中间只有门铃（nginx）牵线。

### 为什么这么设计

- **后端不用伺候前端**：Spring 不再管任何 HTML/JS——train 的 jar 里没有一行前端代码。
- **部署极简**：dist 是纯静态文件，任何静态服务器都能扛；发版＝拷文件。
- **性能极致**：没有模板引擎、没有服务端渲染，nginx 递文件是纳秒级功夫。
- **代价**：需要理解"构建"这个动作，以及 SPA 的路由/缓存玄学（本篇后两场）。

## 3. 配置走查：nginx-reload.sh 如何把 dist 挂进配置（真实行号）

`dist` 目录不是写死的——`infra/nginx-reload.sh` 每次**现场生成** `nginx.conf`，把两个 dist 的绝对路径烙进去。

### 3.1 生成配置的脚本（nginx-reload.sh 真实行号）

```bash
20: TRAIN_DS="$ROOT/frontend/train-ui/dist"
21: TAKEOUT_DS="$ROOT/frontend/takeout-ui/dist"

23: cat > "$NG/nginx.conf" <<EOF     ← heredoc：变量会被展开成真实路径
...
47:     location /train-ui/ {
48:       alias $TRAIN_DS/;        ← 展开：alias /home/icaruslee/Projects/javaweb/frontend/train-ui/dist/;
49:       index index.html;
50:       try_files \$uri /train-ui/index.html;   ← \$uri：转义，让 $uri 原样写进 conf
51:     }
```

**为什么要现场生成**：`$TRAIN_DS` 依赖机器上的绝对路径（谁家的家目录都不一样）。脚本第 12~18 行还有个贴心动作：dist 缺失就先 `npm install && npm run build` 现编一次——首次拉代码也能一键起全栈。

生成的真产物即 `infra/nginx/nginx.conf` 第 24~33 行（真实行号）：

```nginx
24:     location /train-ui/ {
25:       alias /home/icaruslee/Projects/javaweb/frontend/train-ui/dist/;
26:       index index.html;
27:       try_files $uri /train-ui/index.html;
28:     }
29:     location /takeout-ui/ {
30:       alias /home/icaruslee/Projects/javaweb/frontend/takeout-ui/dist/;
31:       index index.html;
32:       try_files $uri /takeout-ui/index.html;
33:     }
```

### 3.2 alias 与 root 的天壤之别

请求 `/train-ui/index.html`：

- **alias**（本项目）：剥掉前缀，去 `.../dist/` 里找 `index.html` → 磁盘 `dist/index.html` ✅
- 假如写成 **root** `root .../dist;`：URL **整段拼接** → 磁盘 `dist/train-ui/index.html` → 不存在 → 404 ❌

**口诀**：alias＝替换（前缀不算数），root＝拼接（URL 原样接上去）。用 alias 时前缀和目录名可以完全无关；用 root 时目录里必须长着和 URL 同名的子目录。

`index index.html;`：访问目录本身（`/train-ui/` 结尾不带文件）时递哪张牌——目录默认页。

## 5. 动手实验二：SPA 的 404 陷阱与 try_files 兜底（今天实测）

### 5.1 先看没有兜底会怎样（思想实验）

SPA 的路由（比如"我的订单"页）往往是前端 JS 自己虚拟出来的 `/train-ui/orders`——磁盘上**根本不存在** `orders` 这个文件。若 nginx 只会老实找文件，用户在"我的订单"页按下 F5 → 404。这是所有 SPA 上线的第一坑。

### 5.2 本项目的兜底实测

```
$ curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9090/train-ui/orders/123
200                        ← 磁盘上没有 orders/123，却是 200！
$ curl -s http://127.0.0.1:9090/train-ui/orders/123 | head -2
<!doctype html>
<html lang="zh-CN">        ← 递出来的正是 index.html
```

### 5.3 读懂 try_files 的执行顺序

```nginx
try_files $uri /train-ui/index.html;
```

- `$uri`：先把请求当文件找（`/train-ui/assets/index-De0t7uFW.js` → 真文件，直接递）；
- 找不到 → 走最后的 `/train-ui/index.html`（**内部重定向**，重新过一遍 location 匹配，仍命中 `/train-ui/`，alias 递出 index.html）。

**一句话**：真文件（js/css/图片）原样递；假路由一律回 index.html，让 Vue Router 接管。

### 5.4 兜底的代价与边界

- 真打错的静态路径（`/train-ui/typo.js`）也会得到 200 + HTML——浏览器解析 HTML 当 JS 会报 `Unexpected token '<'`。这是 SPA fallback 的经典误伤，属正常现象。
- 兜底**只管刷新/直达**，不管路由表里根本没配的路径——那是 Vue Router 自己的 404 页的事。

## 6. 动手实验三：pinned hash——文件名里的缓存通行证（今天实测）

```
$ ls dist/assets/
index-De0t7uFW.js
```

`De0t7uFW` 是 Vite 按**文件内容**算的指纹（content hash）。它的魔法：

| 动作 | 文件名 | 浏览器缓存 |
|---|---|---|
| 改一行业务代码 → rebuild | `index-Cx8kQm2p.js`（hash 变） | 新名字 = 缓存自动失效，必拉新版 |
| 只改 index.html 的标题 | js 的 hash **不变**，html 的内容变 | html 短缓存，js 长缓存不受牵连 |

**这套机制叫"内容寻址 + HTML 引用"**，是前端缓存的黄金组合：

- `index-*.js`：内容永不变 → 可以放肆地 `Cache-Control: max-age=31536000, immutable`（管一年）；
- `index.html`：内容会变（它引用的 js 名字会变）→ 短缓存或不缓存。

两端配合：用户第二次访问时 html 拿到新版 → 发现引用了新 js 名 → 拉新文件；老 js 因名字再也不会被引用，慢慢过期消失。**没有 hash 的话**，你发完版用户还在跑旧 js，只能靠"清缓存"这种玄学。

> 缓存头的实操（`Cache-Control` / `ETag` / 304 协商）在 N03 展开实测——本篇只埋钉子：**hash 是名字，缓存头是政策**，两件事要分开理解。

## 7. 两条路线对照：dev server vs dist 部署

| 维度 | `npm run dev`（5180） | dist + nginx（9090/train-ui/） |
|---|---|---|
| 文件形态 | 源码即时编译，内存里跑 | 打包后死文件 |
| 改代码 | 热更新，毫秒级生效 | 要重跑 `npm run build` + 刷新 |
| API 去向 | Vite proxy → 8084 | nginx 换皮 `/apitrain/` → 8084 |
| 谁在用 | 开发者一个人 | 所有真实访客 |
| 生产可用性 | ❌（Vite 官方明言 dev server 不用于生产） | ✅ |

`infra/nginx-reload.sh` 第 12~18 行的现编逻辑让"clone 即部署"成立：没有 dist 就 build，有 dist 就直接挂。开发日常两开花：改前端开着 `npm run dev`；联调完 build 一次，在 9090 上验"真实形态"。

## 7.5 一个真实的子路径坑（踩过、复现、修好）

早期版本的 dist 有个经典坑：`vite.config.js` 没配 `base`，index.html 里的资源引用是**绝对路径** `/assets/...`——而站点挂在 `/train-ui/` 子路径下，浏览器要的是 `http://127.0.0.1:9090/assets/index-*.js`，这个路径不在任何 location 管辖下：

```
$ curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9090/assets/index-De0t7uFW.js
404                        ← 旧产物：店招错了
```

浏览器从 `/train-ui/` 入口加载时就会得到**白屏**（404 兜底回的 HTML 被当 JS 解析，控制台报 `Unexpected token '<'`）——这正是本册两条入口链接曾"空无一物"的真实原因。

**修复（已应用）**：给 `vite.config.js` 配 `base`，重新 build 即可——

```js
// frontend/train-ui/vite.config.js（takeout-ui 同理配 /takeout-ui/）
export default defineConfig({
  base: '/train-ui/',
  plugins: [vue()],
  ...
})
```

修复后实测：

```
$ curl -s http://127.0.0.1:9090/train-ui/ | grep script
    <script type="module" crossorigin src="/train-ui/assets/index-De0t7uFW.js"></script>
$ curl -s -o /dev/null -w "%{http_code}\n" \
    http://127.0.0.1:9090/train-ui/assets/index-De0t7uFW.js
200                          ← 与 index.html 同源子路径，文件能被找到
```

> **设计意图**：`base` 决定 Vite 把"资源前缀"打进所有产物引用。**部署在子路径就必须配 base**——这是 SPA 子路径部署第一坑（老版本 README 曾保留这个坑当作业，2026-09-14 已修复并复跑全绿）。
---

| 页面白屏、js 404 | index.html 里 `src="/assets/..."` 是绝对路径，但站挂在 `/train-ui/` 子路径下 | 部署在子路径时需给 Vite 配 `base`（第 7.5 节的实弹案例） |

## 9. 自测题（五分钟能答完）

1. `location /train-ui/` 里把 `alias` 换成 `root`，请求 `/train-ui/index.html` 会去磁盘哪个路径找文件？
2. `try_files $uri /train-ui/index.html;` 的最后一段为什么要写**完整 URI**而不是文件名？
3. 改了 `App.vue` 里一行文字，`index-De0t7uFW.js` 的文件名会变吗？`index.html` 的内容会变吗？两者谁必须重拉？
4. SPA fallback 会不会把"真不存在的 js"也兜成 200？这算 bug 吗？
5. dist 里为什么没有 `.vue` 源文件？它们去哪了？

**参考答案**（自测后再看）：

1. `.../dist/train-ui/index.html`（URL 整段拼接）→ 404。alias 是替换，root 是拼接。
2. try_files 的最后一段是**内部重定向**目标，会重新走一遍 location 匹配——必须能再次命中 `/train-ui/` 这个前缀，所以带前缀写全。
3. 文件名会变（hash 按内容算，业务代码变了 hash 必变）；index.html 内容也会变（引用了新 js 名）。html 必须重拉（短缓存），js 新名字必拉、旧名字走缓存自然淘汰。
4. 会兜成 200——这是机制代价而非 bug：nginx 无法区分"前端路由"与"打错的文件名"，只能宁可错兜不可漏兜；前端解析报错即暴露。
5. Vite 把 `.vue` 编译成 JS（模板→render 函数）打包进 bundle；浏览器只认识 js/css/html，源码形态不出门。

## 10. 本节小结

- dist＝构建产物（本项目 2 个文件），nginx alias 直递，后端与前端零耦合。
- `alias`＝替换前缀找文件；`root`＝整段拼接（本项目第 25/30 行用 alias）。
- `try_files $uri /train-ui/index.html;`：真文件直递，假路由回 index.html——SPA 刷新 404 的标准解。
- `nginx-reload.sh` 第 20~21 行定义 dist 变量、第 47~56 行（生成模板）把它们烙进 location。
- `index-De0t7uFW.js` 的 hash＝内容指纹：内容不变名字不变，缓存策略因此可以下狠手（N03 接棒）。
