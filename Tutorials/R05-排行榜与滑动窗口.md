**本站名词卡**

| 名词 | 英文 | 一句人话 | 在本项目哪里见到 |
|---|---|---|---|
| member | 成员 | ZSet 里的"选手"（不允许重复） | 菜名 / tripId |
| score | 分数 | ZSet 的数值，可重复、按分排序 | 成交次数、热度分 |

| fixed window | 固定窗口 | "每 1 秒重置一个计数器"的限流法 | `INCR + EXPIRE 1` |
| 滑动窗口 | sliding window | fixed window 的进阶（本章点到为止） | 末尾"进阶路"一节 |
| TTL | time-to-live | **key 级**倒计时（field 没有） | 限流计数器挂 1s 过期 |

## 1. 生活类比与动机：榜单与闸机，同类不同

两件事表面不相干，底层却是**同一心法的两次发挥**：

- **热度榜** = "谁成交多，谁排前面" → `ZINCRBY + ZREVRANGE`，按分数排队；
- **限流** = "这一秒你来得太多，下一秒再来" → `INCR + EXPIRE 1s`，只在窗口内计数；
- 扣票（R04）= "这一票分毫不差" → `DECR`，原子不超扣。

共同心法都是：**把算术交给 Redis 单线程，Java 只发命令不自己算**（R03 立的心法，本章收成）。

## 2. 购票热度榜：完整代码增量（手把手五步）

目标：**每次下单成功给该车次 +1 分；暴露一个 `/api/train-ranks` 查询前 N 的榜单接口**。教学增量不合并主分支，不改动 BookingService 本体逻辑（只示范挂钩位置）。

### 第 0 步：想清查询形状

- "热度"随**下单事件**发生：写入时机 = `book()` 的成功路径（教学选直插，直观）。
- "榜单"查询 = `ZREVRANGE 0 N-1 WITHSCORES`。
- key 用**全站一个 ZSet**：`train:trip:ranks`，member = tripId。

### 第 1 步：新增一个记录口（`RankService`）

**新文件：`backend/train/src/main/java/com/javaweb/train/service/RankService.java`**

```java
package com.javaweb.train.service;

import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;

// 购票热度榜：ZSet（R05 教学增量，不合并主分支）
@Service
public class RankService {
    public static final String RANK_KEY = "train:trip:ranks";
    private final StringRedisTemplate redis;

    public RankService(StringRedisTemplate redis) {
        this.redis = redis;
    }

    /** 每次下单成功 +1 分（业务成功路径上呼叫）。 */
    public void onBooked(Long tripId) {
        redis.opsForZSet().incrementScore(RANK_KEY, String.valueOf(tripId), 1);
    }

    /** 榜单：前 N 名（从高到低），返回 [member, score] 数组。 */
    public java.util.List<String[]> topN(int n) {
        var entries = redis.opsForZSet().reverseRangeWithScores(RANK_KEY, 0, n - 1);
        if (entries == null) return java.util.List.of();
        return entries.stream()
                .map(e -> new String[]{String.valueOf(e.getValue()), String.valueOf(e.getScore())})
                .toList();
    }
}
```

三处细节：

- **`opsForZSet()`**：ZSet 抽屉的把手（R03 五兄弟的最后一位登场）。
- **`incrementScore`** 译成 `ZINCRBY key 1 member`，原子加分。member 用 `String.valueOf(tripId)`——"Java 类型映射成字符串"又一次演练。
- **`reverseRangeWithScores`** 一次拿回排名 + 分数的成对结果；n 上限在 Controller 里封 20，防全量拉。

### 第 3 步：新增查询接口 `RankController`

**新文件：`backend/train/src/main/java/com/javaweb/train/controller/RankController.java`**

```java
package com.javaweb.train.controller;

import com.javaweb.train.service.RankService;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.Map;

// 购票热度榜（R05 教学增量）：GET /api/train-ranks?n=3
@RestController
@RequestMapping("/api")
public class RankController {
    private final RankService ranks;

    public RankController(RankService ranks) { this.ranks = ranks; }

    @GetMapping("/train-ranks")
    public List<Map<String, Object>> top(@RequestParam(defaultValue = "3") int n) {
        return ranks.topN(Math.min(n, 20)).stream()
                .map(p -> Map.<String, Object>of("tripId", p[0], "score", p[1]))
                .toList();
    }
}
```

**可编译自检**：这一增量只用到教学范围内的东西（`StringRedisTemplate`、`@Service`、`@RestController`、`@RequestParam`、stream）。`mvn -pl train compile` 应当通过；**不合并 main**，只把它当课后研究。

### 第 4 步：现场跑出真实榜单

先用 Redis 侧真实命令给榜喂数据（ZINCRBY 模拟"已成交"），输出一字不差实录：

```
$ redis-cli ZINCRBY pop:shop1 3 芒果糯米饭
"3"
$ redis-cli ZINCRBY pop:shop1 1 咖喱鱼蛋
"1"
$ redis-cli ZREVRANGE pop:shop1 0 -1 WITHSCORES
1) "芒果糯米饭"
2) "3"
3) "咖喱鱼蛋"
4) "1"
```

这就是榜单的真实地基：member=菜名 / score=热度。**把成员换成 tripId，这套命令行就是本章教程的本体**。Java 侧接口若已接入（第 3 步编译后跑过），查询姿态是：

```
$ curl -s "http://127.0.0.1:8084/api/train-ranks?n=2"
[{"tripId":"5","score":"8.0"},{"tripId":"1","score":"3.0"}]
```

读解两行：

- score 出来是 `8.0`（浮点型显示）——Redis 的 score 是浮点域，**Java 侧想取整数自己转**（类型映射心的又一次校勘）。
- `n=2` 只拿头两、`n` 上限封 20：榜单通常**只露前 N**；`ZREVRANGE 0 -1` 全量无底线，生产必防。

## 3. fixed window 限流：平民版"每秒 N 次"

### 思想一句话

**每秒一个新计数器**：`INCR ratelimit:{资源}` + `EXPIRE 1s`——计数第一次入档时挂 TTL，下一秒 key 消散、重新数。一个 key 一秒，过闸就完事。

### 动手验证（真实输出，1 秒闸门的生死）

```
$ redis-cli INCR ratelimit:t5
1
$ redis-cli EXPIRE ratelimit:t5 1
1
$ redis-cli TTL ratelimit:t5
1
$ redis-cli INCR ratelimit:t5
2
$ sleep 1.3
$ redis-cli TTL ratelimit:t5
-2
```

三条命理读法：

1. 第一次 INCR 后来才挂 TTL（也可以 `SET k 0 EX 1` 先挂再 INCR）。**TTL 挂在 key 级**——R02 的 TTL 三态在此拿到第一个战斗用途。
2. `TTL 1` 到 `TTL -2`：**一秒过期即消散**，下一轮 INCR 从 1 开始——**天然重置**，不需要任何清理任务。
3. 闸门判断一行：`INCR` 返回 > N 就拒，否则放行。Java 版只需三行：

```java
Long hits = redis.opsForValue().increment("ratelimit:" + ip);
if (hits != null && hits == 1) redis.expire("ratelimit:" + ip, Duration.ofSeconds(1));
if (hits != null && hits > 5) throw new IllegalStateException("太快了，稍等");
```

**关键坑**：`EXPIRE` 必须在 `hits == 1` 时挂——**若每次都挂**，窗口被无限续命，"每秒 5 次"就永远不会回到 0。

### fixed window 的两大诚实边界

1. **边界缝隙**：第 0.9 秒的 5 次 + 第 1.1 秒的 5 次 = 两秒内 10 次，比"平均每秒 5 次"宽一倍。窗口边界的聚束效应。滑动窗口（多窗加权 / 移动统计）能抹平缝隙，本章只给路标不展开。
2. **窗口粒度**：秒窗高频接口会产生大量短命 key，按业务选窗宽（分钟窗、小时窗），或直接用面向生产的限流模块。

## 6. 参考答案

**练习 1**（实测形态）：

```
$ redis-cli ZINCRBY pop:shop1 1 芒果糯米饭
"4"
$ redis-cli ZSCORE pop:shop1 芒果糯米饭
"4"                        ← 一次真实加分已上账
```

**练习 2**（实测形态）：

```
$ redis-cli ZSCORE pop:shop1 芒果糯米饭
"3"
$ redis-cli ZREVRANK pop:shop1 芒果糯米饭
0                          ← 0 = 第一名（rank 从 0 起）
```

没有 ZSCORE/ZRANK 时，Java 侧要 `ZREVRANGE` 全榜再线下扫 member——**一条 Redis 命令换掉一次全量遍历**，"让 Redis 干它该干的事"再次兑现。

**练习 3**（口径）：`DEL` 等于"榜单全体到家清空"——适合"每日榜单重头"的场景；`ZREM` 适合"把一个成员下架"（如菜品停售）。清榜不要用循环 ZREM 每个成员，那是最啰嗦的路。

**练习 4**（代码思路，可编译不合并）：

```java
@PostMapping("/greet/restrict")
public Map<String, Object> greet() {
    Long hits = redis.opsForValue().increment("ratelimit:greet");
    if (hits != null && hits == 1) redis.expire("ratelimit:greet", Duration.ofSeconds(1));
    if (hits != null && hits > 2) return Map.of("ok", false, "reason", "太快了");
    return Map.of("ok", true);
}
```

实测：一秒内连打三次，应见 `{"ok":true} {"ok":true} {"ok":false,"reason":"太快了"}`——一个微缩的限流闸门作业。**注意第二次不能挂 EXPIRE**，否则窗口永不归零。

## 7. 本节小结

- **ZSet 是按分数排好的队列**：member 不重复（去重天生）、score 可重复（并列有定规）；`ZINCRBY` 与 `ZREVRANGE` 是加分与切榜的两把刀。
- **限流 fixed window** = `INCR + EXPIRE`（一次性挂 TTL）：三行 Java 换一个"每秒 N 次"的闸门；铁律是 **TTL 挂 key 级、只在 hits==1 时挂**。
- 三处共同心法：算术给 Redis（DECR/ZINCRBY/INCR）、key 里编日期或资源名、**每一步留退路**（R04 补偿思想延续）。
- 完整代码增量（RankService + RankController + 挂钩一行 + 限流三行）已全真可编译——**教学增量不合并，手把手不掺水**。
