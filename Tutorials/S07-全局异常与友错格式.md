# S07 全局异常与友错格式

> 主线：本站你走到"广播室"。一个系统最露脸的时刻不是成功，而是**出错时怎么说**。本项目目前错误们还是"各说各话"（框架 JSON、500 假象、状态码错配）——本课给出 S 系列基础七课的收官件：**一个 `@RestControllerAdvice` 的 GlobalExceptionHandler 完整模板**，并说明为何本项目当下没加（这属课后作业，作业步骤一步不落）。
>
> 学完本课你能：写出可复用的全局异常处理器；把 S06 的 500 欠账一次收编成 400/409；把 S05 的默认错误 JSON 升级成项目自己的"错误合同"。

## 本站名词卡

| 名词 | 一句话人话 |
|---|---|
| `@RestControllerAdvice` | 全项目异常值班室：凡 `@RestController` 冒出的异常都可在此登记处理 |
| `@ExceptionHandler(异常类型)` | 值班室里的分诊台：这一类异常归我 |
| 错误合同（Error Body） | 项目自定义的稳定错误 JSON 形状：`{"code","msg","status","path","ts"}` |
| 异常翻译表 | 异常类型 → HTTP 状态码 + 错误码的显式映射 |
| 兜底 handler | `@ExceptionHandler(Exception.class)`——最后防线，防止堆栈外泄 |
| 优雅停机顺序效应 | 异常处理发生在请求线程内；容器停机销毁是另一条时间线（S03） |

## 一、现状盘点（真实证据，全部可复测）

五个后端**当前没有全局异常处理器**。因此你的收到的错误有三个家族：

### 家族 1：Spring Boot 默认 JSON

```json
{"timestamp":"2026-09-14T09:55:17.770+00:00","status":500,"error":"Internal Server Error","path":"/api/bookings"}
```

（S05 实测原话。问题：**业务话术没出场**——为啥下单失败，前端只能去问日志。）

### 家族 2：业务异常全变 500

```bash
curl -s -w '\nHTTP=%{http_code}\n' -m 5 -X POST http://127.0.0.1:8084/api/auth/register \
     -H 'Content-Type: application/json' -d '{"username":"x","password":"pass123"}'
# {"timestamp":"...","status":500,"error":"Internal Server Error","path":"/api/auth/register"}
# HTTP=500
```

（S06 实测原话。问题：**用户名格式错是客户端的锅，却是 500**——监控里看是"服务端不健康"的假信号。）

### 家族 3：状态码语义错误配

- `IllegalStateException("已售罄")`、`IllegalStateException("订单状态不允许支付")`——**业务正常路径上的拒绝**也被算进"内部错误"；
- smoke.py 虽只断言 200/204 不挑错格式，但**你的前端迟早会要求一张稳定形状**。

三个后果：**语义错配、格式不齐、前端合同不稳**。**S 系列基础七课诚实的收官任务**：把这些都收进一个文件。

## 二、完整可复用模板（直接拷贝到任意 Spring Boot 项目）

```java
// GlobalExceptionHandler.java —— 项目统一错误合同（S07 模板 v1.0）

package com.javaweb.train.web;       // 放 train 侧即收编 train 全部 @RestController

import jakarta.servlet.http.HttpServletRequest;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.time.Instant;
import java.util.LinkedHashMap;
import java.util.Map;
import java.util.stream.Collectors;

@RestControllerAdvice
public class GlobalExceptionHandler {
    private static final Logger log = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    /* ---------- 统一错误合同 ---------- */
    private static ResponseEntity<Map<String, Object>> body(
            HttpStatus status, String code, String msg, HttpServletRequest req) {
        Map<String, Object> m = new LinkedHashMap<>();
        m.put("code", code);                  // 稳定错误码（前端据此分支）
        m.put("msg",  msg);                   // 人话一句话（可任意改写文案）
        m.put("status", status.value());      // HTTP 数字码
        m.put("path", req.getRequestURI());
        m.put("ts",   Instant.now().toString());
        return ResponseEntity.status(status).body(m);
    }

    /* ① 请求参数/数据本身不合法 → 400 */
    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<Map<String, Object>> illegalArg(
            IllegalArgumentException e, HttpServletRequest req) {
        return body(HttpStatus.BAD_REQUEST, "BAD_INPUT", e.getMessage(), req);
    }

    /* ② 业务状态冲突（状态机拒绝/权限/重复） → 409 */
    @ExceptionHandler(IllegalStateException.class)
    public ResponseEntity<Map<String, Object>> illegalState(
            IllegalStateException e, HttpServletRequest req) {
        return body(HttpStatus.CONFLICT, "STATE_CONFLICT", e.getMessage(), req);
    }

    /* ③ @Valid 校验失败 → 400 + 各字段明细 */
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, Object>> invalid(
            MethodArgumentNotValidException e, HttpServletRequest req) {
        String detail = e.getBindingResult().getFieldErrors().stream()
                .map(f -> f.getField() + ": " + f.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return body(HttpStatus.BAD_REQUEST, "VALIDATION_FAIL", detail, req);
    }

    /* ④ 兜底：未分类异常 → 500（堆栈只进日志，对外不泄） */
    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, Object>> unknown(
            Exception e, HttpServletRequest req) {
        log.error("unhandled at {}", req.getRequestURI(), e);    // 内部留完整堆栈
        return body(HttpStatus.INTERNAL_SERVER_ERROR, "INTERNAL",
                    "服务器开小差，请稍后再试", req);            // 对外说人话
    }
}
```

### 四条规则的详细读法

1. **一张显式翻译表**：`IllegalArgumentException→400`（请求不好）、`IllegalStateException→409`（状态冲突：车次不存在、不是你的订单、已售罄、非法状态流转）、`@Valid 失败→400+分字段明细`、其他→500。**每个映射都对应着本项目的真实业务异常。**
2. **兜底必须最后**：Spring 按异常族谱挑选 handler（**最近的类型优先**）；`Exception.class` 一枝独大、但放在最末端，只有类型没被前 3 条认领时才会被它接住。
3. **兜内的纪律**：对外只说"服务器开小差"，堆栈全在日志里（`log.error(..., e)`）。**永远不要 e.getMessage() 直接 500 出宫**——那可能是数据库的表结构名或 SQL 摘要。
4. **错误合同 5 字段**：`code/msg/status/path/ts`。它给了前端两个自由：**拿 code 分支（不解析中文）**、**拿 msg 直接展示**。后端改话术，前端代码不动。

## 三、为何本项目当下"没加"？（教学设计的自我交代）

三点相等重要的理由：

1. **错误 JSON 的变更 = 接口契约变更**：所有调用方（Vue 前端、smoke 断言的读者们）**都会**受整形影响。这个变换**应该走一次 PR/联调**，而不是教程顺手改掉代码——读者虽保留学习场景（S05/S06 两个实例都故意的留作"改造前基线"）。
2. **"逐步骤增量"是正经工程习惯**：模板先落地 train 一站 → smoke 全绿 → 改 takeaway / demo 模块 → 最后抽到父工程公共包（backend/pom.xml），一步一步，每一步断言可验。**一次翻车全场、不如小步全绿**。
3. **对照才能学透**： Geoffrey S06 的"500 欠账"与 S05"默认 JSON"，没有改造前的坑就**无感**一个 handler 带来什么。本课的做法是**课程里藏真矩阵**，供读者反向去找。

**因此：全项目改造是一次"课后作业"，步骤在本章；本课只发模板与验收表。**

## 思考题
> **补充小节：收编前后，前端的"分支代码"一页对比。**

收编的价值最终落在**调用方的代码量**上（这决定是否值得做这场"手术"）：

**收编前**（前端要读框架 JSON 的两个口径 + 状态码失真）：

```js
// status=500 不代表服务挂了，要读 status===500 才有用；body 无 code，只能拿 msg 猜
if (res.status === 500) {            // 可能是"用户名重复"这种客户端问题！
  errMsg = res.json && res.json.error === "Internal Server Error"
           ? "操作失败（细节未知，请重试）"
           : "服务器错误";
} else if (res.status === 400) {
  errMsg = res.json && res.json.error === "Bad Request" ? "参数错误" : "错误";
}
// 密码识别错误？用户名存在？——都藏在这个 500 里，前端毫无分支情报。
```

**收编后**（稳定 5 字段合同，一条分支一个业务动作）：

```js
const { code, msg } = await res.json();
switch (code) {
  case "VALIDATION_FAIL":  form.showFieldErrors(msg);  break;   // 逐字段闪红
  case "BAD_INPUT":        toast(msg);                  break;
  case "STATE_CONFLICT":   toast(msg); refreshOrders(); break;
  case "INTERNAL":         toast("稍后再试");            break;
}
// 状态码、错误码、话术三层各司其职：HTTP 层监控用，code 层前端用，msg 层用户用。
```

"手术前后"的直感差异就是这套模板的**存在意义**——这也解释了为什么错误合同在真实团队里通常是**第一号 PR 级工程议题**、而不是教程顺手可改的"小样式"。

1. Spring 怎么在同个 `@RestControllerAdvice` 里挑选 handler？（提示：异常族谱+从此类型到 `Exception.class`，**最近的类型优先**）。若同一异常配了两个不同 handler 会怎样（启动或运行时哪个失败，体验如何）？
2. 把 `IllegalStateException → 409` 是不是一个可讨论映射？"不是你的订单"为什么不该 403？（403 = 身份不足；409 = 资源当前状态冲突。**身份** vs **关系**，两者都对，但需要每个接口认真选。）
3. 现在你的 `@ExceptionHandler(Exception.class)` 捕获了**所有**未分类异常，把 `demo-chat` 的 SSE `stream()` 流**建立后**发生错误算不算它的输乘出货？（提示：流建立后异常发生在**另一个回调线程**，不在请求线程栈内——advice 对它管不到。）
4. 换个视角：哪个模块**不该**收编欢迎 handler？takeaway 的空哨兵接口（GET /menus/999）明明是"没有这家店"，却回 `200 []`——是否要改成 404？（提示：**"没有数据"是成功响应**，客户端按空列表处理是正常；**错误合同**只收编"该成功而没成功"。）

### 参考答案

1. 落地 `com.javaweb.takeaway.web` 后（业务口径）：

```bash
curl -s -o /dev/null -w 'HTTP=%{http_code}\n' -m 5 \
     -X POST http://127.0.0.1:8085/api/rider/<某 CREATED 单号>/deliver \
     -H "Authorization: Bearer <rider9 token>"
# HTTP=409   {"code":"STATE_CONFLICT","msg":"非法状态流转: CREATED -> DELIVERED",...}
```

service 层 `transition()` 原话（`OrderService.java:39-44`）：

```java
if (!LEGAL_NEXT.contains(o.status + "-" + to))
    throw new IllegalStateException("非法状态流转: " + o.status + " -> " + to);
```

正是 409 的翻译源。

2. BizException 版（伪码）：

```java
public class BizException extends RuntimeException {
    public final String code;
    public BizException(String code, String msg) { super(msg); this.code = code; }
}

@ExceptionHandler(BizException.class)
public ResponseEntity<Map<String, Object>> biz(BizException e, HttpServletRequest req) {
    return body(HttpStatus.BAD_REQUEST, e.code, e.getMessage(), req);
}
```

**强**：code 稳定且语义可以精细化（`OUT_OF_STOCK` vs `NOT_YOUR_ORDER`）；**弱**：多一个自定义类、每个业务点都要"记得抛 BizException"——**团队约束成本高于靠 JVM 原生异常映射**。规约建议自下而上：基础七课先把 IllegalStateException 这**一类**端口收编，日后需要更细再引入自定义异常层。

## 本节小结
- 一个文件（`GlobalExceptionHandler`）承接试错契约：**异常类型 → HTTP 状态 + 稳定 code + 人话 msg**。
- 模板四 handler：`IllegalArgumentException→400`、`IllegalStateException→409`、省略话术；`@Valid 编排失败→400+分字段`；`Exception→500 兜底（堆栈只进日志）`。
- 本项目当下"没加"是**教育性留白**（保留 S05/S06 两个"改造前基线"实例）；课后作业给全部落地步骤与回归手段。
- S 系列基础七课到此收官：**跑起→注入→生命周期→路由→响应→校验→异常**，全部在真实代码中。
